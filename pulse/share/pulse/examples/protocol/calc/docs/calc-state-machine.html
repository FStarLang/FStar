calc_sample state machine and layered-log audit map

This clickable artifact documents the verified calculator sample that introduced the raw-byte/message/state proof pattern reused by the TLS client. The authoritative semantic state machine is Calc.Spec.step; the end-to-end proof surface is the Pulse Calc.Server.process_request dispatcher plus the server_exactly predicate.

Audit scope

The sample verifies a stack-based calculator over fixed-size request and response frames. Every accepted request consumes exactly one 5-byte request frame and produces exactly one 5-byte response frame. The semantic state is a list-backed stack with maximum size 10; implementation state is a Pulse heap vector plus size cell, related to the semantic stack by server_exactly.

The key audit claim is not only that each arithmetic operation mutates the stack correctly. Each handler also appends the exact input and output bytes to a monotonic ghost log, proves the new log is consistent, and exposes the single-step relation used by the dispatcher.

Wire format and parse/serialize boundary

request bytes parse_request

Frame shape
Exactly 5 bytes: one-byte tag followed by four big-endian data bytes.
Accepted tags
0 = Push data, 1 = Peek, 2 = Add, 3 = Sub, 4 = Mul, 5 = Div.
Rejected tags
Any other tag parses to None. The top-level dispatcher requires parse_request req_bytes <> None, so invalid tags are outside the accepted theorem path.
Implementation link
parse_tag reads byte 0. parse_push_value reconstructs the big-endian U32 payload for Push.

Spec parser: Calc.Wire L48-L61; Pulse parser: Calc.Impl.Parser L17-L52.

response bytes serialize_response

Frame shape
Exactly 5 bytes with the same [tag:1][data:4] layout.
Response tags
Ok serializes as tag 0 with zero data; Result x serializes as tag 1 with big-endian x; Error serializes as tag 2 with zero data.
Proof support
Handler-local write routines prove their concrete bytes equal serialize_response through serialization lemmas.

Serializer: Calc.Wire L63-L73; serializer lemmas: Calc.Wire L75-L125; result writer: Calc.Impl.Peek L40-L77.

Authoritative semantic state machine

Calc.Spec.step is total: every parsed request returns a new stack and a response. Error cases are semantic transitions, not precondition failures. This makes the log closed over all accepted protocol messages, including stack underflow, overflow, and divide-by-zero requests.

let max_stack_size = 10

Layered log theorem shape

calc_log

The ghost log is the central audit object. It stores raw input bytes, raw output bytes, parsed requests, emitted responses, and the current semantic stack. The initial log has empty bytes, empty traces, and an empty stack.

Type and initial log: Calc.Log L48-L65.

log_consistent

log_consistent log =
  Seq.length log.input_bytes % 5 == 0 /\
  Seq.length log.output_bytes % 5 == 0 /\
  all_parse log.input_bytes /\
  let (state, resps) = run [] log.requests in
  log.current_state == state /\
  log.responses == resps /\
  parse_requests log.input_bytes == log.requests /\
  serialize_responses log.responses `Seq.equal` log.output_bytes

Definition: Calc.Log L75-L87.

log_single_step and log_evolves

log_single_step is the closed one-request evolution relation: one of the six step_log_* functions relates log0 to log1. log_evolves is the reflexive-transitive closure used as the monotonic ghost-reference preorder.

Single-step relation: Calc.Log L179-L208; consistency preservation lemmas: Calc.Log L343-L624.

Functional correspondence per request

Each handler proves the same shape: the new log equals the corresponding step_log_* result, input bytes are old input plus the exact request bytes, output bytes are old output plus the exact response bytes, and server_exactly re-folds with a log satisfying log_consistent.

Dispatcher postcondition: Calc.Server L83-L105; handler postcondition example: Calc.Impl.Push L72-L95.

Implementation proof surface

server_exactly

server_exactly srv log owns the concrete stack vector, size vector, and monotonic ghost log. The vector has length 10, the size cell has length 1, SZ.v size equals the semantic stack length, concrete stack cells match log.current_state in reverse order, and log_consistent log holds.

Definition: Calc.Impl.Types L17-L45.

new_server

Allocation starts from empty concrete stack and size 0, allocates the monotonic ghost reference at initial_log, proves lemma_initial_log_consistent, and returns server_exactly srv initial_log.

Implementation: Calc.Server L37-L59.

process_request

The top-level Pulse theorem for a single request requires ownership of server_exactly srv log0, one 5-byte request buffer, one 5-byte response buffer, and a parseable request. It returns ownership of server_exactly srv log1, preserves the request buffer, owns the response bytes, and proves log_single_step log0 log1 plus exact input/output byte appends.

Dispatcher: Calc.Server L67-L160.
